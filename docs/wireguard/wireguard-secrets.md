# WireGuard Secrets Model
Homelab Network — Router + NAS Unified Control Plane

This document defines how WireGuard secrets (private keys, PSKs, identity material) are managed in the homelab. It covers SOPS encryption, key generation, identity contracts, multi-operator safety, and runtime placement.

## 1. Purpose of the Secrets Model

WireGuard requires:

- private keys for each interface
- public keys for peers
- optional PSKs for additional security
- identity material for router (stored in NVRAM)
- identity material for NAS (stored in runtime state)

The secrets model ensures:

- no private keys ever appear in TSVs
- no private keys ever appear in Git unencrypted
- no private keys ever appear in Makefile output
- router identity is persistent and authoritative
- NAS identity is persistent and authoritative
- multi-operator workflows remain safe

## 2. Storage Locations

# Repo (Git)
Contains:
- SOPS-encrypted YAML files
- TSV templates (no secrets)

Does NOT contain:
- private keys
- PSKs
- runtime configs

# Runtime (/var/lib/homelab/wireguard)
Contains:
- decrypted private keys (RAM-only during generation)
- generated configs
- dirty stamps
- NAS identity material

# Router (NVRAM)
Contains:
- wgs1_priv
- wgs1_pub

This is the authoritative identity for the router WireGuard server.

## 3. SOPS Secrets Files

Secrets are stored under:

wireguard/secrets/*.yaml

Each file is encrypted using SOPS with age keys.

# Example (with # instead of #)

## wireguard/secrets/wg-identities.yaml

interfaces:
  wgs1:
    private_key: ENC[AES256_GCM,data:...,iv:...,tag:...]
  wg7:
    private_key: ENC[AES256_GCM,data:...,iv:...,tag:...]

## wireguard/secrets/wg-peers.yaml

peers:
  laptop:
    psk: ENC[AES256_GCM,data:...,iv:...,tag:...]

## 4. Key Generation Workflow

Keys are generated using wg genkey and wg pubkey.

# Router Identity (wgs1)
Generated automatically if missing:

router-bootstrap-wg-keys:
- checks NVRAM for wgs1_priv and wgs1_pub
- generates new identity if missing
- stores identity in NVRAM
- never writes router private key to disk

# NAS Identity (wg7, wg8, etc.)
Generated by operator:

sops wireguard/secrets/wg-identities.yaml
Add or update private keys.

## 5. Secrets Decryption Workflow

Secrets are decrypted only during config generation:

make wg-generate

The generation script:

- decrypts secrets using SOPS
- loads private keys into environment variables
- writes configs to runtime
- never writes decrypted secrets to repo
- never leaves decrypted secrets on disk (RAM-only)

## 6. Identity Contracts

# Router Identity Contract
- Router identity is authoritative.
- Router private key lives only in NVRAM.
- Router public key is exported to configs.
- Router identity must never be overwritten by repo.

# NAS Identity Contract
- NAS identity is stored in SOPS.
- NAS private keys are decrypted only during generation.
- NAS identity must be stable across generations.
- NAS identity must not be regenerated unless topology changes.

# Peer Identity Contract
- Peer private keys live in SOPS.
- Peer public keys are exported to configs.
- Peer PSKs live in SOPS.

## 7. Multi-Operator Safety

The secrets model ensures:

# No operator can accidentally overwrite router identity
Because router identity lives in NVRAM and is never pulled from repo.

# No operator can accidentally overwrite NAS identity
Because NAS identity lives in SOPS and is versioned.

# No operator can accidentally leak secrets
Because secrets are encrypted at rest and decrypted only in RAM.

# No operator can accidentally deploy stale secrets
Because wg-generate always decrypts fresh secrets.

## 8. Secrets Editing Workflow

# Step 1 — Edit secrets
sops wireguard/secrets/*.yaml

# Step 2 — Commit
git commit -am "Update WG secrets"

# Step 3 — Push
git push

# Step 4 — Pull on homelab host
git pull

# Step 5 — Regenerate configs
make wg-generate

# Step 6 — Install
make wg-install

# Step 7 — Restart
make wg-restart

## 9. Secrets Validation Workflow

# Validate router identity
ssh router "nvram get wgs1_priv"
ssh router "nvram get wgs1_pub"

# Validate NAS identity
sudo wg show wg7
sudo wg show wg8

# Validate peer identity
Check peer public keys in generated configs.

## 10. Emergency Identity Recovery

# Router identity lost
If router NVRAM is wiped:

make router-bootstrap-wg-keys
make wg-install-router
make wg-up-router

# NAS identity lost
If NAS private keys are lost:

Regenerate keys in SOPS:
sops wireguard/secrets/wg-identities.yaml

Then:
make wg-generate
make wg-install-nas
make wg-up-nas

## 11. Summary

The secrets model ensures:

- router identity is authoritative and persistent
- NAS identity is encrypted and versioned
- peer identity is encrypted and versioned
- secrets are decrypted only in RAM
- multi-operator workflows remain safe
- no secrets ever appear in TSVs or Git unencrypted

This is a secure, deterministic, operator-safe WireGuard secrets architecture.
